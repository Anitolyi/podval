= Отчёт по лекции 1: Среда разработки программ для микроконтроллера
:author: Глазырин А.Ю.

== Цель работы

Изучить назначение и состав интегрированной среды разработки IAR Embedded Workbench for Arm, процесс создания исполняемого образа для микроконтроллера, особенности запуска программы до вызова main(), структуру проекта, настройку памяти, стека и кучи, а также закрепить материал практическим проектом на C++ для STM32F411RE.
== Введение

В учебных целях используется интегрированная среда разработки (IDE) **IAR Embedded Workbench for Arm**. Компания IAR предлагает две бесплатные ознакомительные версии:

* **Evaluation** — полный функционал, ограничение по времени использования (30 дней).
* **Kickstart** — ограничение на размер генерируемого исполняемого кода (32 Кбайт), без ограничения по времени.

Для студенческих нужд размера кода в 32 Кбайт достаточно. В курсе применяется **IAR Embedded Workbench for Arm ver 9.10.2**.

== Историческая справка

10–15 лет назад для создания простейших программ хватало текстового редактора, транслятора ассемблерного кода и симуляторов для отладки. С развитием микропроцессоров, ростом объёмов памяти и распространением МК в различных областях техники минимального набора стало недостаточно. Появились редакторы связей (линковщики, компоновщики), отладчики, более совершенные трансляторы, и стало возможным применение компиляторов (примерно с середины 90-х). Возник диалект **Embedded C/C++**. Все эти средства объединили в интегрированные среды разработки (IDE). Одними из лидеров в этой области являются фирмы **IAR Systems**.

== Процесс создания исполняемого образа

Процесс преобразования кода на языке высокого уровня C++ в файл, содержащий образ исполняемой программы, делится на два этапа:

1. **Трансляция кода в объектный файл**
2. **Компоновка кода в исполняемый файл**

=== Трансляция кода

Трансляцию выполняет **компилятор**. На выходе можно получить либо файлы библиотеки (для использования в других проектах), либо объектные файлы.

=== Компоновка кода

Компоновку выполняет **линковщик**. На его входе могут быть:

* внешние библиотеки, полученные на этапе трансляции в других проектах;
* объектные файлы, полученные на предыдущем этапе;
* стандартные (встроенные) библиотеки C++;
* конфигурационный файл, описывающий настройки размещения кода и данных в адресном пространстве микроконтроллера.

Компоновщик создаёт исполняемый файл, который можно запустить на микроконтроллере.

=== Запуск и отладка

Компоновщик IAR создаёт файл в формате **ELF**, который содержит исполняемый образ программы. Этот файл может быть использован для:

* загрузки в систему отладки **IAR C-SPY** или в любой другой отладчик (например, GDB), способный читать формат ELF;
* загрузки образа в ПЗУ микроконтроллера с помощью программатора.

== Запуск программного обеспечения

Функция `int main()` является точкой входа программы: для пользователя программа начинается с вызова этой функции и выполнения её тела. Однако ещё до `main()` микроконтроллер выполняет множество действий: инициализацию стека, глобальных переменных, констант.

=== Инициализация переменных нулевыми значениями

После подачи питания на микроконтроллер:

* в регистр **MSP** (указатель главного стека) загружается значение из первого слова таблицы векторов (по адресу `0x00000000`);
* в счётчик команд **PC** загружается адрес обработчика сброса из второго слова таблицы векторов (по адресу `0x00000004`);
* далее выполняется переход на функцию инициализации.

После инициализации стека выполняется функция инициализации памяти нулями (данные, объявленные как zero-initialized data: неинициализированные глобальные переменные, такие как `int i;`).

=== Запуск функции main()

Завершающий этап — вызов функции `main()`. Перед тем как запустится `main()`, необходимо выполнить инициализацию стека и переменных. Кроме того, если в проекте используются прерывания, в таблицу векторов прерываний необходимо добавить переходы на адреса обработчиков прерываний.

=== Лабораторная работа №1

В данной лабораторной работе был создан код для прошивки микроконтролера STM32F411RE, в результате работы которого создаётся "бегущий огонь" или же "светодиодная ёлочка".
// TODO: [source,cpp]
----
#include "rccregisters.hpp"   // for RCC
#include "gpioaregisters.hpp" // for GPIOA
#include "gpiocregisters.hpp" // for GPIOC

std::uint32_t SystemCoreClock = 16'000'000U;

extern "C" int __low_level_init(void)
{
  // Switch on external 16 MHz oscillator
  RCC::CR::HSION::On::Set();
  while (RCC::CR::HSIRDY::NotReady::IsSet())
  {

  }
  // Switch system clock on external oscillator
  RCC::CFGR::SW::Hsi::Set();
  while (!RCC::CFGR::SWS::Hsi::IsSet())
  {

  }
 
  RCC::APB2ENR::SYSCFGEN::Enable::Set();

  return 1;
}

void delay(int cycles)
{
  for(int i = 0; i < cycles; ++i)    
  {  
    asm volatile("");
  }    
}
int main()
{  
  // Подать тактирование на порт A
  RCC::AHB1ENR::GPIOAEN::Enable::Set();
  // Подать тактирование на порт C
  RCC::AHB1ENR::GPIOCEN::Enable::Set();
  // Порт A.5 на вывод
  GPIOA::MODER::MODER5::Output::Set();
  // Порта C.5, C.8, C.9 на вывод
  GPIOC::MODER::MODER5::Output::Set();
  GPIOC::MODER::MODER8::Output::Set();
  GPIOC::MODER::MODER9::Output::Set();
 
  for(;;)
  {
     GPIOA::ODR::ODR5::High::Set();
     delay(1000000);
     GPIOC::ODR::ODR5::High::Set();
     delay(1000000);
     GPIOC::ODR::ODR9::High::Set();
     delay(1000000);
     GPIOC::ODR::ODR8::High::Set();
     delay(1000000);
     GPIOA::ODR::ODR5::Low::Set();
     delay(1000000);
     GPIOC::ODR::ODR5::Low::Set();
     delay(1000000);
     GPIOC::ODR::ODR9::Low::Set();
     delay(1000000);
     GPIOC::ODR::ODR8::Low::Set();
     delay(1000000);
  }
 
  return 1;
}
----
=== Что делает приведённый код

Код представляет собой простую программу для STM32F411RE, работающую без ОСРВ и использующую регистровые обёртки rccregisters.hpp, gpioaregisters.hpp и gpiocregisters.hpp.

__low_level_init() вызывается на раннем этапе запуска до инициализации среды C++. В этой функции:

включается внутренний тактовый генератор HSI;

ожидается установка флага готовности HSI;

системный тактовый сигнал переключается на HSI;

ожидается подтверждение переключения;

включается тактирование блока SYSCFG;

возвращается 1, что означает продолжение стандартной инициализации.

Комментарий в исходном фрагменте о «внешнем» генераторе неточен: HSION и HSIRDY относятся к внутреннему RC-генератору HSI с частотой около 16 МГц. Глобальная переменная SystemCoreClock = 16'000'000U задаёт ожидаемую частоту ядра для библиотечного кода.

Функция delay() реализует занятую задержку: цикл выполняется заданное число итераций, а пустая ассемблерная вставка asm volatile(""); мешает компилятору полностью удалить цикл при оптимизации.

В main():

включается тактирование портов GPIOA и GPIOC;

выводы PA5, PC5, PC8 и PC9 переводятся в режим выхода;

в бесконечном цикле выводы последовательно устанавливаются в высокий уровень, а затем последовательно сбрасываются в низкий уровень;

между переключениями вызывается delay(1000000), поэтому светодиоды, подключённые к этим выводам, должны включаться и выключаться поочерёдно.

Фактически программа демонстрирует минимальную работу с тактированием и GPIO: настройку тактового генератора, включение тактирования периферии, конфигурацию выводов и управление ими через регистр ODR.

== Результат работы

В ходе выполнения работы был создан проект C++ в IAR Embedded Workbench for Arm для микроконтроллера STM32F411RE. В проект подключён файл начальной инициализации, создана структура папок и групп проекта, настроены параметры компоновщика, размеры стека и кучи. Программа была собрана, загружена в симулятор и проверена в пошаговой отладке. Также была рассмотрена настройка внутрисхемного отладчика ST-Link для загрузки и отладки на реальной плате.

Анализ кода показал, что программа инициализирует тактирование от HSI, настраивает выводы PA5, PC5, PC8, PC9 как выходы и в бесконечном цикле поочерёдно включает и выключает их. Задержка реализована программным циклом.

== Вопросы по разделу

[qanda]
Дайте определение понятию «интегрированная среда разработки»::
Интегрированная среда разработки — это программный комплекс, объединяющий редактор исходного кода, средства сборки, компилятор, компоновщик, отладчик, систему управления проектом и другие инструменты в едином интерфейсе.

Что такое компилятор и чем он отличается от транслятора?::
Транслятор — это общее название программы, преобразующей исходный текст в другую форму. Компилятор является частным случаем транслятора: он переводит программу с языка высокого уровня, например C++, в объектный код или ассемблер, пригодный для дальнейшей компоновки.

Что такое компоновщик и какие функции он выполняет?::
Компоновщик, или линковщик, объединяет объектные файлы и библиотеки, разрешает внешние ссылки и символы, размещает сегменты кода и данных по адресам согласно конфигурационному файлу линкера и формирует исполняемый файл, например в формате ELF.

Почему важен процесс проектирования ПО и какие задачи входят в этот процесс?::
Проектирование важно потому, что позволяет заранее определить архитектуру программы, модули, интерфейсы, требования и ограничения, снизить число ошибок и стоимость переделок. В процесс проектирования входят анализ требований, выбор архитектуры, декомпозиция на модули, проектирование интерфейсов, планирование тестирования и отладки.

Дорисуйте процесс разработки ПО, описанный на изображении IAR_Workbench, с учётом итеративности связей в этом процессе::
На схеме следует показать не только прямой порядок «Design → Develop → Debug», но и обратные связи: из Debug в Develop при обнаружении ошибок реализации и из Develop или Debug в Design при выявлении ошибок архитектуры или требований. Процесс является итеративным: результаты отладки могут приводить к доработке кода и уточнению проекта.

Зачем нужна отладка и в каких случаях она применяется? Для чего применяются точки останова?::
Отладка нужна для поиска, локализации и устранения ошибок в программе, проверки поведения кода на реальном микроконтроллере или в симуляторе, анализа состояния регистров и памяти. Точки останова применяются для приостановки выполнения программы в заданном месте, чтобы inspect-ить переменные, регистры, стек и пошагово выполнять код.

Какие ещё важные характеристики IAR Workbench можно добавить в таблицу iar-features?::
В таблицу можно добавить наличие бесплатных версий Evaluation и Kickstart, генерацию файла ELF, встроенный отладчик C-SPY, поддержку внутрисхемных отладчиков, например ST-Link, формирование map-файла, настройку областей памяти через ICF-файл, анализ размера стека, поддержку C++14/C++17 и сертификацию по стандартам безопасности.
